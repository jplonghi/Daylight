# Daylight design contract

The product is a native macOS countdown collection, with one editor and an independent resizable desktop window for each countdown. The main action is adding an occasion, choosing its date and appearance, then placing its widget. The countdown itself gets the strongest hierarchy; customization stays outside the display windows.

Reference: https://soonenough.app/ (reviewed October 21, 2026). Observed large days-left typography, a draining ring, split-flap digits, restrained rounded widgets and native Mac controls. Daylight uses its own warm ivory editor, charcoal canvas and coral accent. No logos, screenshots or source assets from the reference are reused.

Targets: version 2 has 960x800 editor content (960x828 including its title bar), with a collection strip and login switch. Version 1 used 960x740 content. Widget targets remain 360x320 small, 900x650 large, and 1920x1080 full-screen presentation. The layout uses available width and height, including long titles and large day counts. A large desktop window can move between connected displays without changing system settings.

States: a new countdown starts 30 days ahead and is immediately editable; an empty title uses a clear fallback. Today and past dates show arrival messages and stop at zero. Saves are local and atomic; read failures preserve the original file and offer explicit recovery, write failures show Retry. No network/loading or partial remote data states apply. No calendar, screen recording or accessibility permissions are required by the app.

Accessibility: native labeled controls, keyboard shortcuts, one readable countdown summary, non-color selection indicators, scalable typography and Reduce Motion support. Flip transitions respect Reduce Motion. The calendar-day total uses the user's current calendar/time zone; flip digits show full remaining days, hours and minutes to local midnight.

Implementation: SwiftUI + AppKit, macOS 14+, no packages or network services. This is a freely resizable desktop app, not a WidgetKit gallery extension. It supports normal windows, floating windows, all Spaces and native full screen.

Version 2 behavior: each countdown has its own date, style, palette, window size, visibility and display-relative position. New and Duplicate create independent widgets. An empty collection presents one clear New countdown action. The app remains accessible from a menu-bar ring and has no Dock icon. Closing the editor does not quit. Launch at login uses SMAppService and is enabled for the installed app, with an explicit switch to disable it. After login, visible widgets restore without opening the editor; hidden widgets stay hidden. A missing display falls back to an available display. Full-screen sessions restore as ordinary windows.

Version 2.1 interaction contract: the occasion is the countdown's top heading in every style; the date stays at the bottom. The former decorative slogan is removed. The editor uses visible, horizontally scrolling countdown tabs with a clear selected state instead of a title-only dropdown. New, Duplicate and Delete remain in the collection toolbar. Deletion removes the selected countdown immediately, without Undo or a bottom notification bar. The full visible bounds of style cards, size segments and other custom button labels respond to clicks, including padding and empty space. Target captures: editor at 960 points wide within the available display height (960x771 in this session), 360x320 compact widget, and 900x650 large widget with a long occasion name. Captures in this session have a 2x pixel scale. Retain existing colors, typography and native window behavior. Validate tab switching, deletion/empty state, and edge clicks in an isolated QA profile; retain prior recovery/login evidence for unchanged paths. Selecting a size for a hidden widget must also update its saved dimensions so it reopens at that size.

Migration preserves the existing countdown exactly and backs up the original JSON before writing the version 2 collection. Native tests use a separate bundle identifier and data directory, without registering a login item. Verification details and limits are in evidence/report-v2.json; the original visual baseline remains in evidence/report.json.

Version 2.2 timer contract: New timer opens a focused sheet with 15/25/45/60-minute presets, custom minutes, and a Finish at time for today. Past times are rejected with a visible explanation. A timer is a separate temporary widget using only a draining ring, with second-resolution remaining time and its end time below. Its absolute deadline persists across quit/login and sleep. Completion brings the timer forward and repeats a gentle bundled chime until Acknowledge removes that timer. Other completed timers continue sounding until individually acknowledged. The editor can change a timer's title, appearance and size, but does not offer date-countdown styles or change a running deadline. Cancel/delete removes a timer early. No automatic work/break cycles or notification permissions are added. Check creation, invalid input, running/finished/acknowledged states, concurrent timers, and relaunch in the isolated QA app. Capture the 960-point-wide editor/setup sheet and 360x320 ring timer.

Version 2.3 contract: tiles show only a close control, which hides even a finished timer without deleting it. Remove the hover toolbar and generic days-to-go captions. Double-click a tile to edit it; dragging and resizing remain available. Expose six coordinated background/accent presets in the editor and timer creation sheet, while retaining individual color adjustments. Add X-small at 260x240 points, sharing its minimum bounds with window restoration. Number and Ring numerals have normal digit spacing and safe horizontal padding; inspect 100, 110 and 200 at small sizes for clipped final glyphs. The app uses a regular menu and Dock icon while the editor is open; closing the editor returns to accessory/menu-bar operation without hiding tiles. Validate this lifecycle, close-to-hide persistence, double-click/drag, palette application, all four sizes, and timer acknowledgment at X-small. Capture 260x240 and 360x320 tiles, the editor and timer creation sheet. Existing countdowns and timers must be preserved on installation.

Version 2.4 contract: put New countdown and New timer in the main header; use one compact occasion strip with Show all, Hide all and Delete, without collection labels, counts, duplicate or overflow controls. Remove the individual Open desktop widget action from the editor. Offer exactly ten coordinated named palettes in both editor and timer creation, removing separate background/accent pickers while preserving saved appearances. A single stationary click on a tile selects its occasion when the editor is already visible; double-click still opens a closed editor, and dragging must not select another occasion. Preserve close, resize and timer acknowledgment interactions. Inspect the compact editor and the expanded timer sheet, and verify palette application plus single-click/drag behavior using isolated data before installation.

Version 2.5 contract: hide the native tile close control until the pointer enters the tile, retaining click-to-select, dragging, resizing and close-to-hide. Creation buttons share occasion-tab typography, padding, rounded corners and full-area hit targets. Keep editor dimensions fixed while rendering each selected preset size at its own logical dimensions, scaling down only when it exceeds preview space and labeling dimensions/scale. Add Auto arrange in the editor and menus: show all tiles, order by nearest deadline (timers included), pack left-to-right/top-to-bottom on the editor's display, shrink only as needed with X-small minimum bounds, then use other displays if required. Preserve fullscreen sessions and clearly report capacity limits without overlapping arranged tiles. Persist placements and verify ordering, bounds, spacing, multiple monitors, capacity limits and preview sizes.

Version 2.5.1 correction: Auto arrange groups tiles by their current display, not the editor display. Fit and sort each group independently. Never move a tile to another display, including on overflow; preserve overflow positions and report the capacity limit. Hidden tiles use their restored/saved display. Verify mixed display groups and overflow isolation.

Version 2.5.2 correction: close controls must hide when the pointer moves from a tile to another tile, the editor, another application or desktop. Supplement native tracking with local/global mouse-only event monitors, cleaned up on termination; monitor no keys and request no new permissions. Verify reveal, exit to editor, exit to a different application and close-to-hide.

Version 2.5.3 correction: eliminate competing hover writers in the hosting view and window event override. One shared 80ms sampler computes hover from the actual pointer and frontmost native window, independently of event delivery; TileWindow changes native hidden state only when it changes. Child text tracking areas and layout rebuilds cannot hide/reveal it. Native hit-testing covers pointer movement into other applications, including occlusion. Stop the sampler when no tiles exist. No opacity changes or local/global mouse monitors remain. Check multiple title/number/background positions, exit and return.

Version 2.6 contract: add Day grid alongside Number, Ring and Flip clock for date countdowns; timers remain Ring. Each square is a calendar day from the progress start date to the target (target exclusive). Elapsed days are solid accent, upcoming days dim, and today outlined. Fit a balanced grid of small rounded squares at every preset size, bounded to 600 cells for extreme dates; grouped cells show an explicit days-per-square label and partial fill intensity. Keep the occasion heading and target date footer without adding a generic days-to-go label. Share the existing start-date control as Progress timeline. Expose Grid in the editor and View menu (Cmd4), preserve older styles and saved countdowns. Verify civil-day/DST boundaries, arrival, future starts, grouped ranges, persistence, and X-small/dense/large rendered cases.

Version 2.6.1 interaction contract: retain AppKit NSWindow/SwiftUI rendering, but replace per-event manual frame positioning with NSWindow.performDrag(with:) using the original mouse-down event after a small drag threshold. Preserve single-click selection, double-click editing and native close/resize/acknowledgment hit regions. Never depend on receiving mouse-up after the native handoff. Move/resize notifications debounce placement publication until 350ms of quiet; close, quit, full-screen transition and end-of-live-resize flush the current frame. Programmatic arrangement/resizing must continue saving actual final positions. Validate click/double-click, native handoff, placement persistence and existing UI. Do not substitute synthetic-event frame stepping if UI automation cannot drive Window Server dragging, and do not claim a physical smoothness measurement from synthetic input.
